# 药到 · 给爸妈的 AI 用药管家

> 基于 **小聆 AI（ListenAI）** 平台 + **Arcs Mini3** 开发板的嵌入式语音小应用。
> 一句「我每天早饭后吃一片降压药」，它复述确认、存在云端、第二天还记得。
> 老人不会用智能手机，但一定会说话——这就是做它的理由。

---

## 它解决什么

慢病老人每天要吃的药又多又杂：饭前饭后、一天几次、每次几粒，记不住也讲不清。
子女不在身边，纸质的药单常常想不起「今天吃没吃」。

「药到」把这件事变成**一句话的事**：

- 说一句服药规律 → 它解析、复述确认、云端建档；
- 问「今天该吃什么」→ 它按**早 / 午 / 晚**分组念给你听；
- 说「我吃过了」→ 它打卡、夸你一句；
- 问「我这周按时了吗」→ 它出一份**当日用药小结**；
- 举着药盒说「帮我拍个照记上」→ 它**识别照片、念出认到的内容，再一项一项跟你确认**；
- 问「能不能停药」→ 它老实说「这事得问您大夫」。

## 能力一览（5 个本地工具 + 1 个拍照识别处理器）

| 工具 / 处理器 | 触发 | 做了什么 |
|---|---|---|
| `med_plan_save` | 「我每天早饭后吃一片降压药」 | 解析药名 / 次数 / 饭前饭后 / 剂量 / 时间，存云端，复述确认「您听听对不对？」 |
| `med_plan_list` | 「我要吃哪些药 / 早上该吃什么」 | 返回**已按餐次分组**的全部计划，适合直接念 |
| `med_take` | 「降压药我吃过了」 | 记录一次打卡，加一句鼓励；药没建档会顺手提醒 |
| `med_plan_delete` | 「我停吃 XX 了，不用记了」 | 复述药名确认后删除（仅用户明确要删才调用） |
| `med_report` | 「我今天吃药情况怎样 / 有没有漏吃」 | 纯本地 KV 计算当日依从性：应服几次、已服几次、还差几次 |
| `med_snooze` | 「等会儿再提醒我 / 过10分钟再叫我」 | 把已到期未打卡的提醒推迟 5–120 分钟，到期自动重新播报 |
| `MedPromptBuilder`（每轮确定性注入） | 任意唤醒/对话轮次 | 纯代码计算到期剂量 → system 注入【到药提醒】；同槽位只提醒一次 |
| `MedicinePhotoHandler`（图片处理器） | 「帮我拍个照记上」/ 设备拍照 | 调视觉模型识别药盒 → 解析成草稿 → 口语化念出已识别内容，并**一项一项确认**缺失项，全齐后由 `med_plan_save` 落库 |

> 工具结果通过 `confirm_text` 回传，由 Agent 完整念给用户，并主动复述药名 / 时间 / 剂量。
> 拍照识别走独立的 `imageHandler` 扩展点（不占用 ReAct 工具槽位），无论图片来自设备 `take_photo` 能力还是直接传入，都会进入识别流程。

## 拍照识别建档（多步确认）

老人举着药盒说「帮我拍个照记上」，设备拍照后进入识别流程：

1. **识别**：`MedicinePhotoHandler` 把图片交给视觉模型（带专用 system prompt，要求输出结构化 JSON），解析出药名 / 每天几次 / 饭前饭后 / 每次剂量 / 时间点。
2. **念出已识别内容**：「我帮您看了看照片，这盒药大概是【阿莫西林胶囊】，一天 3 次、饭后吃、一次 2 粒。」
3. **一项一项确认**（适老化关键）：认不清的项（如餐次、具体时间）它会**一次只问一件**——「是饭前吃还是饭后吃呀？」用户回答后接着问下一项，直到齐全。
4. **落库**：全部确认齐后由 `med_plan_save` 写入云端，并复述「您听听对不对？」。

识别结果会暂存到 KV（`yaodao.photo_draft.<deviceId>`），中途不用重新拍照；即使某轮历史被裁剪，草稿也不丢。

> **安全前提**：识别只是辅助，绝不替用户臆测药量或疗程。认不清就如实说「没看清」，让用户口述补充；照片里压根不是药时，直接转为口述建档。

实现拆解：
- `src/medVision.ts`：**纯逻辑**（视觉输出解析、缺字段判定、下一步提问、摘要、历史标记），不依赖运行环境，可单测；
- `src/medicinePhotoHandler.ts`：实现 `ImageTurnHandler`，负责调模型 + 状态持久化 + 错误降级；
- `agent.ts`：通过 `createOfficialVoiceAgent({ imageHandler })` 挂上处理器，并在 `systemPrompt` 增加「拍照建档」多步确认指令。

## 架构

```
        ┌─────────────┐   语音    ┌──────────────────────────┐
 老人 ─▶│ Arcs Mini3  │◀────────▶│  自定义云端 Agent           │
        │ (小屏设备)  │   文本    │  @listenai/agent-sdk       │
        └─────────────┘          │  · systemPrompt（人设+安全）│
                                 │  · MedToolProvider（5 工具）│
                                 │  · ReAct 工具循环           │
                                 └──────────────────────────┘
                                              │
                              ┌───────────────┼────────────────┐
                              ▼                ▼                ▼
                        Host KV 存储      平台长期记忆        平台 TTS
                      （按设备 ID 隔离）  （快照兜底）        （语音播报）
```

- **端侧零固件改动**：只写入 Product ID / Secret 绑定应用，设备 ID 注册进 OTA 白名单。
- **设备隔离存储**：用药计划与打卡按 `yaodao.meds.<deviceId>` / `yaodao.doses.<deviceId>` 隔离，每台设备最多 20 条计划 / 100 条打卡。
- **记忆兜底**：KV 未命中时，从平台长期记忆里召回最近一次用药计划快照，避免「断电就失忆」。

## 安全边界（这是它最被看重的点）

药到**只做提醒、记录、复述和转述医生嘱咐**，绝不越界：

- 不推荐任何药物、剂量或疗程；
- 问「能不能停药 / 要不要加量 / 换什么药」→ 「这个问题要问您的大夫，我不敢替您拿主意。需要我提醒您复诊时问一下吗？」
- 用户说身体不舒服 → 认真对待，建议联系家人或就医；
- 紧急情况（胸痛、呼吸困难、摔倒等）→ 第一时间建议拨打 **120** 并联系家人。

## 适老化设计要点（来自用户研究与同类产品验证）

- **一次只问一件事**：缺信息时只问一个缺失项（「这个药每天早上吃几次？」），降低认知负担；
- **主动复述确认**：建档 / 打卡后把关键信息完整念一遍，避免听错记错；
- **按餐次分组播报**：问「早上吃什么」直接给早餐段，不把全部药名堆给老人；
- **温和共情**：漏服时不指责，提醒补服要听大夫，并主动问「要不要我帮您记个提醒？」；
- **本地 / 云端隔离**：用药数据按设备保存，隐私不出本设备域。

## 变更记录

### v1.2.0（2026-11-08）——到药主动提醒

**新能力：到药主动提醒（确定性注入，不依赖模型自觉）**
- 每轮对话开始时，`MedPromptBuilder` 用纯代码计算「到期的、还没打卡的、没播报过的」剂量，命中就在 system 提示词里注入【到药提醒】指令，模型会先提醒吃药再回答问题；
- 播报过的槽位登记到 KV（`yaodao.announced.<deviceId>`），同一槽位只提醒一次；
- 用户说「等会儿再提醒我」→ `med_snooze` 工具推迟 5–120 分钟，到期自动重新播报；
- 无具体时间的计划按餐次兜底（早饭→07:30、午饭→12:00、晚饭→18:00、睡前→21:30；「随时吃」不做主动提醒）；
- 共享 `MedStore` 统一 KV 访问，Provider 与 PromptBuilder 同一实例、同一设备键。

**架构新增**：`src/medStore.ts`（存储 + 到期计算纯函数）、`src/medPromptBuilder.ts`（提示词注入）。

**测试**：20 → 35 个单元测试（新增槽位展开、到期判定、贪睡、防重复、设备隔离 5 组共 15 个）；typecheck + test 全绿。

**E2E 实录**：建「01:02 吃 Test药」→ 01:02:47 问「现在几点」→ 回复「……正好是您刚才记的 Test药 的时间，该吃了」；再问天气不再重复提醒。

**边界**：主动提醒发生在「用户唤醒设备的下一轮对话」，无人唤醒时设备不会自己开口（云端 Agent 无推送 API，需端侧固件定时开场，见路线图）。

### v1.1.0（2026-11-07）

**修复**
- **时区边界（严重）**：「今天」此前按 UTC 计算，北京时间 0:00–8:00 的打卡会被统计到昨天，依从性小结出错。现在 `nowString()` / `dayString()` 统一按北京时间（UTC+8），打卡间隔与日期边界一致。
- **时间归一**：建档时间串校验范围（`25:99` 被丢弃），支持单数字（`8:5` → `08:05`）。
- **「睡前」分组语义**：原来「睡前吃药」被错分到晚餐段，现独立为「睡前」。

**加固**
- **重复打卡防护**：同一药 120 秒内再次 `med_take` 不重复记录，改为温和确认（防语音回声/重复唤醒虚报依从性）。
- **输入钳制**：药名 ≤40 字、剂量 ≤20 字、`per_day` 封顶 12、时间点上限 14 个——LLM 传参不可信，服务端兜底。
- **小结覆盖无建档场景**：有打卡但没建档时，报告打卡次数并引导建档，而不是拒绝统计。
- **拍照建档闭环**：`med_plan_save` 落库后自动清理对应 `photo_draft`，避免旧草稿串药。

**测试**：16 → 20 个单元测试（新增时区边界、重复打卡、钳制、睡前分组 4 组）；`npm run typecheck` + `npm test` 全绿；v1.1.0 已部署测试链路并完成 5 项端云 E2E 验证（含重复打卡防护真机命中）。

### v1.0.x（2026-10-30 ~ 11-06）

v1.0.0 首版（4 工具 + KV 存储）；v1.0.1 增加平台长期记忆镜像；v1.0.2 镜像改为全量快照，缓解云端多实例间 KV 隔离导致的数据「时有时无」。

### 已知限制

- **KV 按云端运行实例隔离**：设备会话固定在同一实例时数据一致；换实例时靠「平台长期记忆快照」兜底，极端情况下可能读到稍旧状态。语音流程已做优雅降级（查不到就引导重新说一句）。
- **拍照识别的 recall 兜底**：记忆索引有秒级延迟，识别后立刻查询可能命中不到；主路径（KV）不受影响。
- **到点主动开口提醒**仍未实现（需设备端定时 + 云端推送，见下方路线）。
