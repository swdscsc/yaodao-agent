## 一、项目目标与定位
- 一条约 **240 秒（4 分钟）** 的中文科技产品纪录片。
- 项目名：**药到**；定位：**给爸妈的 AI 用药管家**。
- 平台关系：跑在 **小聆 AI 平台 + 聆思 Arcs Mini3 开发板** 上；药到是开发者基于开放平台**自行开发的应用**，非厂家原生功能，也**不是开发板或硬件设备本身**。

## 二、画面风格与禁忌
- 风格：科技产品纪录片 / 真实生活场景 / **Kinetic Editorial 动态排版** / 克制、温暖、专业。
- 视觉主体：**真实产品操作**（cloud_A–H 实拍 + 真实设备运行画面）。
- **禁忌（明确）**：廉价 AI 科技宣传片腔；PPT 卡片拼接感。→ 优先用动态排版承担信息，静态卡片只作点缀，且避免堆砌。
- 画幅：**1080×1920（竖屏 9:16）**；**保持真实素材 30fps（实测 30 / 30.01 / 30.02），不强制插帧**；母版规格可采用 30fps，但不篡改检测数据。

## 五、真实性分级定义（L1–L4 统一口径，PHASE2-05）
> 本定义适用于全部五份 Phase 2 文件；`phase2_shot_list.csv` 第 9 列已按本口径标准化（7 个纯 B-roll 镜头由 L1 降为 L2；SH15 / SH19 改为 `L2 + L3` 组合；SH24 卡片不再标 L1），**该 CSV 的时间码、素材来源、画面内容、旁白、字幕、转场、音效 7 列均未改动**，因此 PHASE2-05 的 692 字 / 176.2247s 预算口径仍可复算。完整取证见 `phase2_functional_footage_evidence.md` §0。

- **L1 真实功能操作画面**：有实际操作证据（连续可见的用户操作 / 设备界面交互 / 屏幕文字）。
  - **证据边界（必须遵守）**：屏幕文字只能证明「该文字 / UI 在该时刻出现在真实设备屏幕上」，**不得外推**为后台数据写入成功、语音识别准确、数据库一致性、闹钟到点触发或设备主动开口播报。
  - cloud_A R1–R5 的设备交互界面、cloud_H「举起药盒拍照」动作、cloud_A 00:05:30「这个问题要问您的大夫」属此级。
  - cloud_H 仍须拆分：拍照动作 = L1；「认出药名 / 用法」「认不清时逐项追问」**无真实结果证据**，属 L3。
- **L2 真实设备 B-roll**：只证明设备画面真实，**不证明旁白描述的功能实际发生**。
  - 设备外观 / 静置 / 运行界面长镜头（cloud_B/C/D/E/F/G 的 B-roll 部分）属此级。
  - **SH15、SH19 允许 `L2 真实设备画面 + L3 功能说明` 组合，但不得描述为真实功能演示。**
- **L3 代码 / 架构 / 动态排版 / 功能说明**：不冒充真实设备反馈；**不生成任何虚构的设备对话气泡、语音反馈或成功提示动画**。
  - Lua 提醒器代码为真实实现证据，但「到点主动播报」的实机录屏缺失；不得因有代码而认定播报已成功演示。

## 六、动态排版（Kinetic Editorial）策略
- 信息主体用**动态排版**（关键句逐字 / 逐行入场、轻微位移与缩放），而非静态卡片堆叠。
- 卡片仅用于 S5 收尾（card_end_v）与点缀；其余段尽量不用卡片，避免 PPT 拼接观感。
- 字号 ≥ 60px（1080 宽），白字 + 半透明深色蒙版，确保竖屏移动端可读。
- 节奏：S1/S5 留白多；S4 现场声为主、画面快切（smoothup 连续感）。

## 七、音频策略
- 人声：c1–c9（最终旁白）；旧版 n01–n08（60s v1）**不使用**。
- 床声：bgm_ambient.wav 低音量铺底，旁白时侧链避让。
- SFX：whoosh（转场 -18dB）、chime（功能卡 / 到点）、success（到点播报时刻，若实拍含现场声则压低）。
- 响度目标：-14 LUFS，TP -1.5dB（沿用 footage_analysis.md 设定）。
- **诚实标注**：c1–c9 在 PHASE2-04 / PHASE2-05 复核后**仍未听审**（无 transcript、无离线 ASR、禁云端转录）；音频—画面匹配须待人工听审 + 建立映射后再核验。PHASE2-05 已给出 `phase2_audio_shot_mapping.csv`（9 段映射全部 UNKNOWN）与 `phase2_duration_budget.md`（实测 125.46s / 240s，目标文案两口径 183.61s / 176.22s 均为估算）。
