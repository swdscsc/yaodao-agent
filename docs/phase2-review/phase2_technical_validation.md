## 二、Vidova 元数据 vs 本地清单 差异解释（标注为解释性推断）
- **差异现象**：本地 `footage_inventory.json` / `cloud_inventory.json` 记录全部为 **1080×1920**；
  而 Vidova `asset list` 报告 A/B/C/D/G/H = **608×1080**、E/F = **1920×1080**。
- **差异根因（解释性推断，未独立证实）**：Vidova 的 `width/height` 很可能为其**代理（proxy / 转码缩略）尺寸**，而非原始尺寸。理由：
  - 竖屏原始 1080×1920 → 若代理仅缩小像素，约得 608×1080（同 9:16），与 A–D/G/H 报告吻合；
  - E/F 报告为 1920×1080（横），与 ffmpeg 实测竖屏 1080×1920 矛盾，疑似代理转码时的旋转 / 转置呈现。
  - **但本环境未对 Vidova 服务端做独立取证（如读取其代理生成管线 / 直接比对代理文件），故"代理尺寸"属合理推断，非已证实结论。**
- **处置（保守）**：
  - 母版尺寸以 ffmpeg 实测 **1080×1920** 为准，**不要**以 Vidova 的 width/height 设序列。
  - 本地清单的 1080×1920 记录与 ffmpeg 一致；即便差异确为代理尺寸，也非素材损坏。

## 四、字幕安全区与可读性
- 画幅 1080×1920（竖）。**标题安全区**：水平居中 90%（x≈54–1026px），避免贴边。
- **字幕位置**：底部 15% 区带（y≈1500–1800px），单屏不超过 2 行。
- **字号**：正文 ≥ 60px，关键句可 ≥ 84px；行距 ≥ 1.2×字号。
- **可读性**：白字（#FFFFFF）+ 半透明深色蒙版（rgba(0,0,0,0.45)）或投影；避免浅色字压亮背景。
- **平台留边**：抖音 / 视频号竖屏有 9:16 安全框，关键内容内缩至中央 80% 区域，防被 UI 遮挡。
